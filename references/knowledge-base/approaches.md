# Approaches, workarounds and design patterns seen in real cores
Status labels follow the knowledge-base ladder. Everything here is a lead unless it cites an entry that is validated.

1. **Claim the save size from the core (KB-001).** Continuously write `has_save ? size : 0` (NES) or a fixed size once a save exists (NGPC) into the size-table entry of the save slot's *position*. Simplest fix for "save file never appears".
2. **Persist only what changed (NGPC).** Track dirty flash blocks, stage them in PSRAM, CRC-bind to the cartridge identity, apply before boot, flush through a demuxed bridge-read region. Trades MiSTer .sav compatibility for a sub-64 KB slot (see KB-003).
3. **Carry the cartridge inside the savestate (NGPC).** Embed the save image in the savestate blob so Memories/sleep rewind machine and cart atomically (96 KB states).
4. **Soft-CPU as bridge master.** LiteX RISC-V (agg23), NEORV32 (Paprium), Neogeo Overdrive's soft CPU: run firmware that owns the file API, interact registers and asset handling, instead of hard FSMs. Lets you iterate on load/save logic without a 25-minute fit; interact entries can be mapped to a register window (LiteX: 0x1000_0100..0x1000_013C = indices 0-15 with a changed-flag per entry).
5. **UART/JTAG over the dev cart or USB Blaster.** Devkit cart gives 2 Mbps UART for logs and program hot-reload without touching SD (needs cartridge_adapter 0). A JTAG UART works with a genuine Blaster.
6. **Split bitstreams + Chip32 chooser.** Big cores ship several bitstreams (PAL/NTSC, system variants, SNES chips) and let a Chip32 program or `<instance>.json core_select` pick one, instead of runtime PLL reconfig (KB-015).
7. **Deferload + target commands for big or dynamic data.** Keep ROMs on the SD card and stream on demand with 0180 (`data_loader`-style consumption); watch the per-slot file cache (switching slots discards it).
8. **Chip32 emulator loop.** agg23's `openfpga-chip32-sim` lets Chip32 loaders be tested on a PC before hardware.
9. **Reduce fit risk with discipline (KB-011/KB-012).** Archive every fit report and bitstream hash, re-seed 3-4 times, gate on setup/TNS/hold plus a boot smoke test rather than ALM count, and confirm the bitstream actually changed after firmware-only edits.
10. **Firmware-config through interact.json.** Persisted interact values are written into core registers before Reset Exit and are the one documented persistence path that needs no core-side file handling.
11. **Multi-bit CDC done right.** Use `sync_fifo.sv` from analogue-pocket-utils for buses; keep single-bit `synch_3` for flags (KB-009).
12. **Audio/data IP reuse.** `sound_i2s.sv` (I2S, FIFO sync, signed/unsigned), `data_loader.sv`/`data_unloader.sv` (bridge <-> byte/word memory), `psram.sv` (Pocket-timed PSRAM), `hex_loader.v`, `debug_key.v`.
13. **Declare an `address` on the nonvolatile save slot and serve bridge reads there (KB-004).** NGPC, K3V GBA and openfpgaSDK all do; use ready/valid handshakes rather than a fixed-latency `data_unloader` over variable-latency memory (KB-026).
10. **Test ladder by turnaround time.** Lint and JSON validation (seconds), host and block simulation (minutes), whole-core simulation with a scripted host, synthesis and report gates, the full fit, then the device. Push every decision down the ladder; the device trip is the scarce step. Lead, not validated.
11. **Cheap Pocket-specific checks that catch repeated mistakes.** Validate every core JSON file (the Pocket gives almost no feedback on malformed JSON); compare the SHA-256 of the `.rbf_r` on the card with the build output (stale bitstream); parse the map and fit reports for resource budget, inferred RAM mode (KB-052, KB-058), ignored SDC constraints (KB-027), and setup and hold in both corners (KB-011); grep for per-bit `synch_3` on buses (KB-009); check cartridge and link tie-offs. Lead, not validated.
12. **A trace channel with no extra hardware.** Send event ids with target 0152 (KB-241) and read them from the debug log (KB-242); combine with firmware counters exposed over MMIO (KB-082). Needs a core-side sender, since the template never issues 0152 (KB-007).
13. **Unattended reflash-and-retest.** A JTAG reload re-runs the whole load with the same starting conditions (KB-243), so a script can reflash, run a self-test and read results from the log or a JTAG read. Never use a clone USB Blaster on the Pocket (KB-018). Untested end to end.
14. **Self-testing diagnostic build.** One card install runs a battery of checks and shows every verdict on one page that is captured as a screenshot, so a single human trip answers many questions (for example with a pixel-grid report code). Lead, not validated.
15. **A reusable debug link and a way to choose one.** A register window over Virtual JTAG (pure RTL: REQ, RSP and ID frames, JTAG-clock crossing, bus timeout), an adapter for a JTAG-to-Avalon master's exported port, a byte stream as registers (a console without the Nios tools), and a chooser script that ranks report codes, the 0152 log, ISSP, SignalTap, the window, the master bridge, JTAG UART and serial links from facts read out of the project. Public kit: the `pocket-testkit` repository (`methods/debug-links/`: `rtl/`, `host/`, `CHOOSING.md`, `tools/choose_link.py`; overview of every testing method in `methods/README.md`). Simulated with iverilog only, not fitted or run on a Pocket; see KB-245 to KB-247 for the vendor-side rules.
16. **What a Pocket host model must exercise in a whole-core simulation.** Beyond boot order and bridge reads (KB-008): the three persistence paths and the shutdown flush (nonvolatile slots from the size table, target write/flush on deferload slots, interact persist values; KB-001, KB-007); savestate and sleep round trips (KB-016, KB-017); the display-mode command that demands a grayscale response word of 16'h444D; the docked-state notification (host 00B2); heartbeat loss and a JTAG reload re-running the whole load (KB-243); data-loader backpressure (KB-028); and interact values written before reset exit. These are the common Pocket-only failure classes; a module test cannot see them. Lead, not validated.
17. **Test Chip32 loaders on a PC first.** agg23's chip32 simulator (approach 8) runs a loader program without a Pocket; pair it with Debug Logging and Chip32 Exec Log on hardware (KB-242). Pause Core Boot and Pause Load Data have no effect when Chip32 runs, so SignalTap arming for early loads differs.
18. **Caveats on the reusable Virtual JTAG window (item 15) before trusting it.** Confirm the quartus_stp return format of the DR shift (hex or binary) with the `id` frame; compile the sld_virtual_jtag wrapper to check port names; check the map report for how the byte-stream FIFOs were inferred (KB-052, KB-058); declare the JTAG clock and the user clock asynchronous in the SDC; one master port only, so build an arbiter before using two links at once.
