# Open questions (unknowns worth a hardware test or a source read)
Add an entry with `scripts/kb.py new` once a question has a claim to test; record the result in the entry.

| # | Question | Why it matters | Cheapest test |
|---|---|---|---|
| OQ-1 | Does Pocket service target 0188 (flush), and with what handshake? No public core implements it. | Persistence design. | Minimal core issuing 0188 for a nonvolatile slot; log result codes and timing; repeat after a successful 0184 write. |
| OQ-2 | Is the size-table entry used by shutdown flush the one at the save slot's data.json POSITION (KB-001), and is it nonzero at Quit? | Save file stays zero. | Read the table back over the bridge before Quit; write a distinctive size; check Saves/. |
| OQ-3 | Does the (size mod 0x10000) delivery truncation (KB-003) still exist on current firmware? | Confounds any slot >= 64 KB. | 0x10200-byte pattern slot, log delivered bytes. |
| OQ-4 | Is 0184 write reliable on current firmware (KB-005)? | Alternative persistence route. | Run the kbmouse-targetdata example unmodified. |
| OQ-5 | Which firmware version is on the test Pocket and which framework version does core.json require? | Behavior differs by version. | Settings > About; record it with every result. |
| OQ-6 | SDRAM: CAS latency, dram_clk phase and refresh vs intermittent return-path faults (KB-021, KB-011). | Persistent SDRAM faults. | Sweep CAS 2/3 and clock phase; correlate with per-seed hold slack. |
| OQ-7 | Exact bridge read timing: cycles between `bridge_rd` and required data. Docs say only 'up to the next read strobe'. | Return-path design. | SignalTap `bridge_rd`, `bridge_addr`, `bridge_rd_data` on back-to-back reads. |
| OQ-8 | What does APF do when the core changes the size-table entry of a nonvolatile slot at runtime? | Growing/shrinking saves. | Resize the entry at runtime, Quit, compare file length. |
| OQ-9 | What lives only in Analogue's Discord (#openfpga-dev) and is not written anywhere public? | Possibly undocumented behaviors. | A person pastes threads; log as community-reported with link/date/author. |
| OQ-10 | Is `PHYSICAL_SYNTHESIS_EFFORT` (Normal/Extra/Fast) selectable in Quartus Lite for Cyclone V, and does Extra recover timing on marginal builds? Fit reports show "Normal". | Untested timing lever. | Set Extra in a copy of the .qsf, rebuild the same seed, compare setup/hold and compile time. |
| OQ-11 | Which of the "Lite lacks X" claims (incremental compilation, design partitioning, Rapid Recompile) are true for Lite 25.1 on Cyclone V? | Decides which build-time reductions are usable. | Try each in the GUI/qsf on a Lite install and read the report or warning text. |
| OQ-12 | Do array widths chosen for M10K (native x5/x10/x20/x40 and x8/x16/x32) pack without wasted bits in your fit report? | RAM budget on a nearly full device. | Compare the memory-block count in the fit report for candidate widths. |
| OQ-13 | Is a Gray-coded video line counter (clk_vid to the CPU clock, 3-stage synchroniser) a reliable beam position on Cyclone V, including around the wrap? | Tear-free drawing by racing the beam. | Read the counter from firmware while the beam runs; log the decoded row against a known frame and count wrong reads near the wrap. |
| OQ-14 | Can a core open a file by absolute path, in a SUBFOLDER of its common assets, into a second declared data slot with target command 0192 (as it can for the audio slot, KB-043)? | Any per-album sidecar file (cover images, metadata). | Declare a spare deferload slot with an extension, open `/Assets/<core>/common/<album>/<sub>/file.bin` into it, read the first 16 bytes back. A project cover reader is the first test; log the result as a note with `kb.py note`. |
| OQ-15 | How fast and how lossless is target 0152 (Debug Event Log)? Is Debug Logging available on every unit, not only developer units? | Decides whether it can be a trace channel for testers (KB-241, KB-242). | Core-side event sender, 1000-event burst plus a steady rate; read /System/Logs/ and count, check ordering and timestamp resolution. |
| OQ-16 | Is a timing report after synthesis only (before placement) close enough to the final slack to gate on? | Cheap early timing gate. | Run it on three past builds and compare with the final fit slack, setup and hold, both corners. |
| OQ-17 | Does Verilator build the APF files and Altera primitives, or is iverilog the practical choice? | Coverage tooling for whole-core simulation. | Elaborate a template core with Verilator and `altera_mf.v`; record what fails. |
| OQ-18 | What is the real logic and RAM cost of a JTAG-to-Avalon master or virtual JTAG block in a Pocket core, and can a script then read any register? | Whether a scripted desk link is affordable on a nearly full device. | Add one gated master to a template core, fit, compare resource counts, read a register through System Console (KB-057). |
| OQ-19 | Can a core accept button input from a register (OR-ed with the real controller bits) so an agent can drive menus unattended? | Fully unattended device tests. | Add a register ORed into the controller path of a template core and drive it over JTAG. |
| OQ-20 | Does a free simulator compile `altera_lnsim.sv` for `altera_pll`, or must the PLL always be hand-modelled (KB-244)? | Fidelity of whole-core simulation. | Compile the model and run a lock and phase-shift test. |
| OQ-21 | Does a Virtual JTAG register window (pocket-testkit `methods/debug-links/rtl/jtag/pk_vjtag_regwin.sv`) fit and work in a Pocket core: DR bit order, TDO timing, primitive port names, and its logic cost with the SLD hub? | The cheapest scripted link for an agent; its cost is not published anywhere found (OQ-18). | Instantiate `pk_vjtag_debug` in a template core, fit, read per-entity utilisation, run `quartus_stp -t host/pk_vjtag.tcl id` (in `methods/debug-links/`) (expects 0x504B0101) after a JTAG reload. |
| OQ-22 | Is nios2-terminal available in the Quartus Lite install used for Pocket fits (KB-247), and does System Console's master service work through the Pocket's JTAG chain? | Decides whether JTAG UART or the master bridge are usable without extra installs. | Look for the tools in the install; run `jtagconfig` then a System Console `get_service_paths master`. |
| OQ-23 | Where are the user1/user2 pads, what voltage do they run at, and does a retail unit route them (KB-249)? | A cable-free serial route by the JTAG header; shorter than a link cable. | Find continuity to the FPGA pins named user1/user2, measure the idle level, drive user1 from a core and scope it. |
| OQ-24 | Can a soft RISC-V core's JTAG debug module be bit-banged over the four link pins to a cheap FTDI MPSSE adapter and OpenOCD, for GDB halt, step and memory access? | Debug firmware with the shell closed, without Quartus. | Loopback test the four pins at 1 to 6 MHz first (KB-013), then a debug module in a template core with an FT2232H or FT232H, 3.3 V only. Check the debug module's licence before use. |
| OQ-25 | Does `device_virtual_dr_shift` return the captured value in hex only when `-value_in_hex` is given, or always in binary? | A wrong assumption makes every Virtual JTAG read decode wrongly. | Run an `id` frame through quartus_stp and print the raw return with and without the flag. |
| OQ-26 | Does the `altera_attribute AUTO_SHIFT_REGISTER_RECOGNITION OFF` on a 3-bit vector register stop synchroniser chains becoming ALTSHIFT_TAPS (KB-010), and is a SYNCHRONIZER_IDENTIFICATION assignment accepted in Lite for Cyclone V? | The toggle synchroniser must stay as flops. | Fit a small design with the attribute, search the fitter report for ALTSHIFT_TAPS and for synchroniser identification entries. |
